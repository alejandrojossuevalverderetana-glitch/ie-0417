## Proceso de desarrollo de software

### Etapas de desarrollo de software

Recoleccion y analisis de requerimentos:
(Produt Owner, Project Manager, Busines Analyst, CTO)

Diseño del sistema y del software: (System Architect, UX/UI designer)

Implementacion (codificacion): (Front-end developer, Back-end developer)

Pruebas (testing): (Solutions Architect, QA Engineer, Tester, DevOps)

Despliegue: (Data administrator, DevOps)

Mantenimiento:
Este nunca acaba pues se debe hacer constantemente (Users, Testers, Suport managers)

### Que es un modelo de proceso de desarrollo?

Es una estrategia estructurado que guia como se hacen las etapas del desarrollo, permite adaptar el proceso segun el tipo de proyecto

### Modelos de proceso

- Modelo cascada (se va en orden, hasta no terminar una fase no se pasa a la siguiente)
- Modelo espiral (Toma elementos en cascada y de desarrollo iterativo se centra en analisis de riesgo)
- Modelo incremental (Se van implementando cosas poco a poco, entregando minimos viables desde muy temprano)
- Modelo iterativo (Se va mejorando poco a poco desde una version inicial y luego se va refinando con sucesivas iteraciones)

### Desarrollo agil

Se utiliza en proyectos que cambian de forma muy constante, se trabaja con sprints de 1 a 4 semanas, en cada sprint se incluyen:

- planificacion
- desarrollo
- pruebas
- revision del cliente
- retrospectiva

cada 3 sprints (esto puede variar) se entrega una release

#### Scrum

Tiene roles definidos, sprints fijos y reuniones clave.

#### Kanban

Flujo continuo, sin sprints definidos, enfocado en visualizar el trabajo (tablero Kanban), tiene un limite de tareas definido, entrega continua.

# Clase 2 (Tarea)

## Resumen General

Una metodologia de desarrollo de software es una manera estructurada de organizar y planificar como se va a llevar a cabo un proyecto de software, busca hacer entregas de calidad con los requisitos definidos.

## Principales enfoques

### Metodologias secuenciales

Siguen un flujo lineal, una vez que se pasa una fase no se suele volver a la misma, se sigue adelante.

**Ventajas:**

- Planificacion clara y predecible

- Documentacion detallada

- Buena gestion de proyectos con requisitos estables

**Limitaciones:**

- Poca flexibilidad

- Riesgo de entregar un producto que no cumpla las expectativas finales

Es especialmente util para proyectos muy bien definidos que no van a cambiar en el tiempo.

### Metodologias ágiles

Nacen como respuesta a la rigidez de los modelos secuenciales, y buscan solucionar sus problemas con flexibilidad y sprints cortos en los que se hacen iteraciones continuas.

**Ventajas:**

- Entregas frecuentes y útiles desde el inicio.

- Adaptación constante a cambios en requisitos.

- Mayor involucramiento del cliente.

**Limitaciones:**

- Difícil estimar tiempo y costo total del proyecto.

- Menos documentación, lo que complica auditorías.

- Requiere equipos disciplinados y con experiencia.

Util para proyectos que varian constantemente o requieren entregas continuas para realizar cambios o ajustes, por lo que actualmente es muy utilizado el 71% de las empresas usan Agile en su ciclo de desarrollo.

## Criterios para elegir una metodologia

Al seleccionar una metodologia se deberian considerar los siguientes puntos:

- Tamaño y complejidad del proyecto

- Nivel de riesgo aceptable

- Flexibilidad requerida

- Documentacion necesaria

- Capacidades y cantidad del equipo

## Tendencias recientes y observaciones clave

Se pueden observar detalles importantes como:

- Creciente uso de enfoques híbridos (ej. Agile + DevOps), combinando adaptabilidad con automatización y despliegue continuo.

- DevOps potencia la integración y entrega continua (CI/CD), ideal para SaaS.

- El mercado de DevOps alcanzó $10.7 B en 2023 y sigue en crecimiento con una tasa anual de 22 %.

- Agile escalado (ej. SAFe, LeSS, Scrum of Scrums) se usa en empresas grandes con múltiples equipos.

- Sectores con restricciones regulatorias o infraestructura física tienden a mantener enfoques más secuenciales o híbridos, para balancear flexibilidad con cumplimiento normativo.

## Opinion personal

Considero que todas las metodologias pueden llegar a ser utiles dependiendo del enfoque que se le quiera dar a un proyecto.

- Los enfoques tipo Agil son utiles para proyectos variables que el usuario final quiere ver como van evolucionando poco a poco y haciendo cambios sobre la marcha, por ejemplo paginas web o aplicaciones moviles.

- Por otro lado si se tiene tiempo para realizar el proyecto o se requiere un producto final bastante robusto y terminado las metodologias secuenciales pueden ser más utiles, como por ejemplo en un sistema bancario, donde el usuario busca un producto final bien pulido y facil de mantener, además probablemente no requiera hacer demasiados cambios durante el desarrollo.
